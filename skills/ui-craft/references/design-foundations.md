# 视觉基础与实现判断

## 先选方向，再定义数值

用两三个明确形容词约束视觉，而不是堆砌风格词。以下是起点，按品牌与业务调整：

| 方向 | 适用 | 视觉机制 | 常见误用 |
| --- | --- | --- | --- |
| 安静、精准、产品导向 | 科技产品、工具、作品展示 | 中性色、强主视觉、少量强调、清晰字阶 | 过量留白使功能与信息消失 |
| 温暖、自然、编辑感 | 生活方式、文化、内容品牌 | 暖中性底、材质/摄影、错落版式 | 低对比小字、装饰压过内容 |
| 理性、清晰、高效率 | 企业服务、运营工作台 | 稳定栅格、语义状态、密度可控 | 每块都包卡片、所有文字一样大 |
| 沉静、精密、可感知 | 监控、能源、交通、制造 | 暗底分层、少量高亮、趋势与空间关系 | 霓虹泛滥、无单位数字、装饰地图 |
| 鲜明、活跃、行动导向 | 活动、电商、青年品牌 | 单一大胆主色、紧凑节奏、直接 CTA | 全部元素都争抢注意力 |

## 字体与中文排版

- 无现成品牌字体时使用系统字体栈：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。不要假设外部字体在国内网络一定可用。正文不依赖远程字体加载完成。
- 中文正文通常从 14–16px、行高 1.6–1.8 试起；密集系统界面可用 13–14px，但关键任务信息不能被迫阅读细小文字。移动正文优先 16px。大屏应按观看距离重新放大。
- 标题字阶先确定 3–5 个角色：页标题、区块标题、正文、辅助说明、关键数字。字重通常 400/500/600 已足够；不要以全局粗体制造层级。
- 中文标题避免机械加大字距、奇怪断行与孤字。英文大写标签可少量使用，不能替代中文信息。长文限制行宽，正文左对齐比居中更适合持续阅读。
- 指标与表格数字使用 `font-variant-numeric: tabular-nums`；数字、单位与比较基准分层，避免所有内容同样醒目。金额小数位、百分比精度、日期格式在同一页面一致。
- 文本由容器自然换行，必要时用 `min-width: 0`、`overflow-wrap` 处理长字符串。仅在确有空间约束时截断，并提供可发现的完整信息路径。

## 栅格与节奏

- 常见桌面内容最大宽度可从 1200–1440px 选择；边距可从 `clamp(20px, 4vw, 64px)` 起步。系统平台允许更宽以容纳数据；不要强加官网窄列。
- 用 4/8px 为基础的间距序列，按“元素内 < 组件内 < 组件间 < 区块间”形成分组。相邻内容若关系相同，间距应相同。
- 页面可有非对称布局，但标题、图像、正文与操作仍应有共同对齐线。每屏只需一个主要视觉焦点；其余信息以尺度、位置和留白支持它。
- 卡片用于表达独立对象、可比较集合或独立操作，不是所有区块的默认容器。连续阅读可用分隔、分栏和版面留白。嵌套卡片容易造成边框噪音。
- 圆角采用少量层级，例如控件 8px、卡片 16px、英雄主视觉 24px；具体值服从品牌。胶囊不是所有按钮、标签和面板的默认形状。

## 色彩、素材与图标

- 先定义页面底、表面、浮层、主文字、次文字、分隔线、品牌动作、成功/警告/错误等语义，再选择色值。深色主题重新设计表面与对比，不直接反转颜色。
- 通常一个主强调色足够。危险色留给风险与破坏操作；营销强调与错误状态不能混淆。图表类别色与状态色分别管理。
- 文字与背景使用适当对比；普通文字以 4.5:1、大文字以 3:1、必要控件边界与焦点以 3:1 作为通用检查目标。半透明层要在最终合成背景上检查，不只比较 CSS 色值。
- 图像应解释产品、空间、人物或使用情境；避免无关图库照片。优先用户资产、可合法使用的素材或原创图形。图片设尺寸/比例，核心主视觉优先加载，屏外内容按需加载；提供合适替代文本。
- 图标使用统一来源、光学尺寸和线宽，不混用 emoji 与线性图标作为同级导航。纯装饰图标隐藏于辅助技术，图标按钮有可访问名称。

## 动效与响应式

若用户能调整主题或文字，结合[外观偏好、阅读位置与动态反馈](appearance-and-reading.md)检查系统偏好变化和排版重排后的任务位置。

- 状态反馈通常可从 120–200ms、面板出现从 200–320ms 试起；大幅空间动画应克制。优先 `transform`/`opacity`，避免持续触发布局。
- 支持 `prefers-reduced-motion`。不要以动画作为唯一状态提示；不要为阅读设置必须等待的入场序列。
- 用内容决定断点，参考 390/768/1440px 检查，但不只追求三个截图。手机将多列折叠、缩减边距并重排操作，保留核心任务。固定定位元素不能覆盖正文或系统安全区域。
- 控件命中区域通常向 44px 靠拢；桌面紧凑控件可更小，但仍应易于命中。触屏不能依赖 hover。对横向数据表提供明确滚动容器，不能让整页横向溢出。

## 组件状态与工程落地

组件至少考虑默认、悬停/焦点、选中、禁用；数据区域按业务需要设计加载、空、失败、部分结果、权限不足与成功。只实现当前场景需要的状态，不用一整套无关组件膨胀项目。

表单标签与输入关联，说明在输入前可知；错误靠近字段并说明修正方法。弹窗开启后合理管理焦点、支持 Escape，关闭后返回触发位置。避免用 div 复制原生 button、select、details 的语义与键盘行为。

先利用项目已有技术与组件。单页本地示例可用内联 CSS/JS 的 HTML，无需为展示引入构建系统。复杂业务才按状态/组件边界组织代码。声明并清理监听器与定时器；不让动画和自动刷新在后台无限消耗资源。真实业务不把敏感数据写进前端源码或原型 localStorage。
