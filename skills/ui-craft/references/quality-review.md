# 交付与视觉评审

## 先检查真实行为

选择当前页面的主路径进行端到端手动或自动检查，不要求为每个 CSS 调整新增测试。最低证据应覆盖：页面可加载、无阻断控制台错误、主要操作有实际结果、关键状态正确、无意外横向溢出。

官网可检查导航与主 CTA、移动菜单、表单状态；平台可检查搜索/筛选/重置、详情、保存与结果变化；大屏可检查范围切换、单位/图例、更新时间与全屏。测试涉及真实提交、付款或外部操作时遵守用户授权范围，不为了测试产生未经授权的业务副作用。

本地 HTML 检查链接与文件引用存在；无网络资源时可离线展示。启动服务后验证实际 HTTP 响应，再报告 URL 与端口；不把未启动的地址当作完成。只绑定本机即可满足本地评审，不擅自公开发布。

## 视觉检查顺序

1. **整体缩略看结构**：第一眼能否看到主题、主要内容与行动？是否存在争抢注意力的元素？区块密度是否与任务一致？
2. **正常尺寸看阅读**：中文断行、字体回退、次文字对比、数字对齐、图表标签、长标题与真实内容是否成立？
3. **窄屏看重排**：常用行动是否可达？固定元素是否遮挡？表格是否局部滚动？主视觉是否裁切错误？
4. **操作后看状态**：选择、空结果、错误、弹窗、长内容是否破坏版式？焦点是否仍可见？

推荐代表性视口：390×844、768×1024、1440×900；大屏再检查目标比例。它们是检查起点，不是“只支持这些像素”。浏览器缩放至 200% 时，普通网站与平台的核心信息和操作应仍可用。

## 用内容变化暴露缺陷

只选与当前交付有关的场景。记录操作、视口和实际可见结果，修正后复查同一条件。

| 场景 | 如何检查 | 需要修复的可见结果 |
| --- | --- | --- |
| 活动或产品首屏 | 用最长实际标题和真实日期，在 390px 宽度及桌面查看主视觉，打开首要入口 | 题名被遮挡、日期断成难读碎片、照片主体被裁出画面，或入口指向空区域 |
| 筛选平台记录 | 查找一个具体名称，再增加会产生零结果的条件，然后清除筛选 | 记录和数量不一致、残留上一页选择、空结果缺少返回完整列表的操作 |
| 大屏追查异常 | 从告警记录找到所属区域和指标，切换时间范围，在目标分辨率核对刻度、单位、时点 | 记录无法关联区域、图表仍展示旧范围，或关键轴标与单位相互遮挡 |
| 调度图表 | 用同一时刻的零值站、缺报站和下一时刻的预测切换区域，从区域趋势找到需处置的站点 | 缺报站挤进缺车榜、部分站点小计标为全区总量，或未来预测出现在当前库存中 |
| 手机预约 | 选定座位，从图、摘要核对座号，再切换到该座位已占用的场次，滚到最末排 | 摘要保留失效选择、还能提交已占座位，或末排被底部操作条盖住 |
| 选择与焦点 | 仅用键盘经过关键选项、执行主操作，核对焦点、选择语义和结果信息 | 焦点消失、无法通过键盘选中，或读屏只能听到孤立的“按钮”而无对象名称 |

图像截图可以帮助判断首屏主次和裁切。筛选、选择失效、提交状态及焦点恢复需要在真实交互后检查。现场远距大屏的可读性由目标设备与观看距离复核。

## 质量门槛

以下是修复阻断项，不用审美得分抵消：主要操作无效；文本被遮挡；手机整页横向溢出；关键内容不可读；焦点陷阱或无法关闭弹窗；把模拟数据/行为声称为真实；数据图表与标签矛盾。

非阻断视觉问题可按影响排序：页面主题不清 → 信息层级弱 → 版面密度不当 → 不一致组件 → 装饰细节。先修前者，不用增加阴影掩盖结构问题。

如需要量化评审，可用下面的辅助量表，每项 1–5 分并附具体观察；它不是客观审美证明，也不应成为机械追分目标：

| 维度 | 观察依据 |
| --- | --- |
| 场景适配 | 是否服务目标用户与主要任务 |
| 信息层级 | 标题、正文、操作、状态的优先级是否清晰 |
| 视觉一致 | 排版、间距、色彩与组件是否有统一规律 |
| 内容与可信度 | 内容具体、数据一致、来源与模拟边界清楚 |
| 交互完整 | 关键操作、反馈、异常恢复与键盘路径可用 |
| 跨设备可读性 | 窄屏、缩放与目标大屏下可阅读和操作 |

## 交付说明

给用户正在运行的入口、文件位置、主要评审操作与已知限制。报告“验证了什么”而非空泛的“测试全部通过”。如果浏览器不可用，说明仅进行了哪些静态检查，并保留视觉待验项。不要把尚未完成的模拟原型称为生产级系统。
