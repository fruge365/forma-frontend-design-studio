# 业务平台、管理系统与工作台

## 从任务组织页面

先确定常用任务和对象：例如“查找订单 → 判断异常 → 查看详情 → 处理或转派”。围绕这一流程布置导航、筛选、数据和操作。首页不必总是统计看板；若用户主要处理待办，待办队列应优先于漂亮但无用的指标。

区分全局导航、当前模块与页内视图。避免左侧导航、顶部导航、标签导航同时重复同一层级。保留明确的当前位置、返回路径与上下文。窄屏可折叠侧栏，但不能把常用行动藏到难找的位置。

## 密度与层级

- 页面标题与关键行动构成第一层；筛选/搜索构成第二层；主体数据占据主要空间。辅助说明、批量操作与分页按任务距离放置。
- 系统平台的精致感来自稳定的节奏、清楚的对齐与正确的信息密度。不要套用官网的巨型标题和大段装饰留白；也不要为了“专业”把文字压到 11px。
- 统计卡只保留帮助决策的指标。每项说明统计范围、单位和周期；趋势方向要符合语义，错误率下降不应该标红。
- 控件高度、边框、图标、表头、行间距保持一致。重要行通过信息内容与适度强调突出，避免整张表彩虹色标签。

## 表格、列表与检索

目录包含多组筛选、候选对比或跨页选择时，先确定查询条件和作用对象，再组织工具栏、行操作与返回路径。[搜索、筛选与选择范围](discovery-selection.md)

表格适合需要横向比较的记录，卡片适合视觉对象或信息结构差异较大的一组对象。不要仅为手机适配而把全部复杂表格变成重复卡片；可以保留关键列、详情展开或局部横滚。

- 搜索字段与筛选范围明确；输入后结果真的变化。提交方式、回车行为与清除动作一致。筛选变化后同步更新数量与分页；无结果提供清除筛选。
- 排序列显示方向，排序依据与数据类型一致；数字不按字符串排序。分页、选中项和批量操作的作用范围明确。
- 行操作优先展示最常用项，其余收进菜单。危险操作与普通操作分开；能撤销的操作优先提供撤销，重大不可逆操作才增加确认。
- 行点击与行内按钮不应冲突。选择复选框具有标签，选中状态可见。筛选后隐藏的选择不应悄悄参与批量操作。
- 数据为空、无搜索结果和加载失败是不同状态，文案与下一步不同。不要把失败显示成空列表。

## 表单与详情

遇到条件字段、跨步骤核对或多角色交接时，按当前选择决定要校验、展示和提交哪些信息。具体设计见[分步办理、核对与退补](transaction-flows.md)。

字段顺序按用户理解组织，相关字段分组。标签持续可见，不用 placeholder 代替标签。格式、限制与示例在出错前说明。保存时防止重复提交；失败保留已填内容，指出可修正原因。

详情侧栏适合快速浏览且保留列表上下文；复杂编辑使用独立页。抽屉/弹窗需要标题、明确关闭方式、焦点管理与必要滚动。未保存更改的退出提示只在确有更改时出现。

通知区分“操作已完成”“处理正在进行”“需要用户处理”。toast 适合轻反馈，不能成为唯一错误信息，也不能替代真正的数据变化。服务端任务提供可追踪状态，原型任务明确标注本地模拟。

现场用手机处理一组重复异常时，可把已定义的处置措施做成选择项，把补充事实留给备注。需要取证或解释原因的流程仍应明确必填内容。把设备状态和工单状态分别命名：为 38 °C 高温事件保存措施后，可以显示“高温 · 已记录”；判断恢复要等新的传感读数。可撤销记录的页面，撤销后同步恢复待处理计数与可执行操作。

## 可访问性与适配

键盘可完成主要工作流，焦点能被看见，表格结构有语义，状态变化按需要通过 live region 通知。图标按钮有名称，禁用原因可理解。高密度平台可以保留桌面优势，但手机仍需可读、可导航、可查看关键详情。

## 手机预约与选座

多厅共用入口时，把“从入口到哪个厅”与“进入该厅后如何找座”分开表达。跨厅同号不等于同一座位；场次切换与回执归属见[地图、平面图与地点列表](spatial-interfaces.md)。

- 将用户需要做的判断放在同一流程里。先确定日期或场次，再选择位置，最后核对。活动页跳转到预约页时传递适用的活动或场次信息，返回后能找到原来的项目。
- 座位图保留通道、分区和座号的关系。触控区域可以大于图形本身，但相邻热区要互不重叠。给每个可交互座位可读名称，例如“A 区 08 号，可选”，并用选中状态、勾选符号与文字摘要反馈当前选择。使用键盘和读屏时也能得知占用原因。
- 日期、时段或区域改变后，用新范围的可用数据核对选择。若座位失效就清除旧选择并解释原因，底部摘要、可用数量和提交状态一起更新。真实预约在提交时由服务端校验可用性，原型版需能在本机查看刚才的预约结果。
- 手机底部操作区预留安全区和正文末尾的等量空间。用双行摘要、最长区域名和最末排座位试排，保证最后一个可选项能滚到操作区上方。

## 模拟内容的可信边界

原型可用固定、内部一致的数据，顶部或说明处标记“模拟数据”。筛选、汇总、导出应基于同一数据源；不要点击筛选仅换标题，图表却不变。导出文件包含当前筛选范围或明确声明全部数据。用户输入以文本渲染，避免把自由文本拼进 `innerHTML`。
