# App、微信小程序与移动网页

先确认交付载体和进入页面的方式。同一品牌可共享名称、字体气质和动作色，技术栈与使用频率决定导航、首屏与返回路径。项目已采用 SwiftUI、Compose、Flutter、uni-app 或其他框架时，沿用其导航和组件，并检查目标端编译后的交互。

## 从进入方式决定页面

| 场景 | 进入后先看到什么 | 操作和返回 |
| --- | --- | --- |
| 技师每天反复打开巡检 App | 本班待办、当前工单、地点与上次进度。任务足够多且确有多个同级目的地时再设底部导航 | 打开工单、登记处理、回到原班次和选中项。现场中断后能认出草稿，区分本机保存、待传与服务器已接收 |
| 访客扫码进入园区报修小程序 | 扫码带入的楼栋或设备，以及当前可办事项。缺少或失效的入口参数时提供选择地点 | 选问题、核对、提交、看回执。由分享直接进入回执详情时，提供可用的业务入口。返回编辑保留所填内容 |
| 用户从消息、搜索或外部链接打开 H5 | 具备独立含义的标题、对象和下一步。能从地址重建的筛选或详情写进 URL | 浏览器返回、刷新和复制链接都可到达合乎预期的页面。直接进入的首个页面应有明确的站内去向 |

小程序也可以承载高频工具，App 也可以接受扫码直达。遇到这种需求，按实际进入方式和用户任务重新选择上表的组织方式。

## 消费类页面怎样排

| 用户要完成的事 | 先占据屏幕的内容 | 返回与中断后核对 |
| --- | --- | --- |
| 购物选规格、确认订单 | 商品与关键差异并列，选定规格后同步价格、库存与主操作。多个相似套餐用同一顺序展示关键差异 | 从确认页返回应保留规格和数量。库存变化时说明受影响的选择，给出重选入口 |
| 阅读内容、学习课程 | 阅读页给正文和字级留空间，目录与笔记按需展开。课表以日期或章节组织，给出上次阅读位置 | 从目录、搜索或笔记回正文时回到对应段落，调大字号后仍能找到当前章节 |
| 到店预约、查找附近服务 | 地点、可约时段与剩余名额决定主次。若距离影响决策，可让地图与可操作的地点列表联动 | 定位不可用时仍可手选地点。切换门店后核对原时段和价格是否仍然有效 |
| 聊天、社区回复 | 阅读消息时让对话或主题占据主要面积，输入框与回复对象相邻，键盘弹出后可见当前输入 | 返回会话保留未发送草稿和阅读位置，用文字区分发送中、失败和已送达 |

## 将规则落实到运行环境

**iOS 与 Android App。** 区分顶层目的地切换和详情压栈，尽量沿用系统返回手势、屏幕阅读与文字放大的能力。窄窗口让列表与详情逐层进入，宽窗口可并排展示；折叠、旋转或分屏后保留正在看的对象。平台的安全区或窗口 Insets 用于避开系统栏及手势区，已经由容器处理的区域无需再加一层间距。[Android 自适应布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/canonical-layouts) · [Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)

iOS 可以 44 × 44 pt 的常用触控面积试排。Android 用 dp 表示布局和触控范围、sp 表示文字，交互控件通常预留至少 48 × 48 dp。图标绘制区可小于热区。同一组长标签应在系统大字体下试排，再决定是否改成双行或展开页。[Apple 界面设计建议](https://developer.apple.com/design/tips/) · [Android 单位](https://developer.android.com/design/ui/mobile/guides/layout-and-content/grids-and-units) · [Android 触控范围](https://developer.android.com/guide/topics/ui/accessibility/apps)

**微信小程序。** 需要从表单返回继续编辑时，把详情作为普通页面入栈。原生路由中，`wx.navigateTo` 保留当前页并打开非 tabBar 页面，`wx.navigateBack` 回上一层。`wx.switchTab` 用于配置过的 tabBar 页面，并关闭非 tabBar 页面，切换前需处理仍要保留的草稿。分享、扫码或重新启动可能只有一层页面栈，此时根据业务提供“回到工单”或“继续办理”等入口。自定义导航使用 `wx.getMenuButtonBoundingClientRect()` 判断右上角菜单位置，结合当前窗口与安全区处理变体。保留系统导航时直接使用宿主提供的标题和返回操作。[微信小程序官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)

WXSS 的 rpx 按屏宽折算，常规 750rpx 对应一屏宽。例如在 375px 宽度下 88rpx 约为 44px，在 320px 宽度下约为 37.5px。可用 rpx 表达随宽度变化的尺寸，常用控件再按实际逻辑像素检查热区和文字。微信官方 WeUI 同时提供 px 和 rpx 样式版本。[腾讯小程序渲染层单位说明](https://www.tencentcloud.com/document/product/1219/61744) · [微信 WeUI WXSS](https://github.com/Tencent/weui-wxss)

**H5 与内嵌 WebView。** CSS px、rem、可用视口和浏览器历史决定网页表现。页面采用边到边布局时，可用 `env(safe-area-inset-bottom, 0px)` 调整底部操作区，正文末尾同时预留操作区所占高度。键盘弹出时核对当前输入框、字段错误及提交操作能否通过滚动抵达。外壳已留出安全区时，以内嵌网页真实可见范围为准。[WebKit 安全区与边到边布局](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)

## 权限、回执与验证范围

- 有扫码地点就展示它，让用户核对。由用户点“定位附近点位”或“拍摄现场”时，再解释用途并按该端相关接口请求所需权限。拒绝、取消或设备无此能力时，保留已填内容，按业务提供手动选点、输入编号或跳过可选附件。仅在业务确实需要当前能力时说明继续办理的条件。
- 草稿和回执需要不同的标识。弱网时可在本机保存草稿，服务端确认后再显示真实单号和提交结果。支持自动重试的真实业务应能按请求标识查询或去重。HTML 演示可以发放本地演示回执，在用户查看结果的位置写明存放范围。
- 浏览器样页可验证文字、布局、键盘焦点、返回时资料保留、刷新恢复和模拟提交。原生 App 另外验证系统返回、旋转、安全区、大字体、系统键盘和离线再连接。微信版在开发者工具检查路由、入口参数及基础库兼容，再用目标微信真机验证胶囊、键盘、授权与回到小程序。记录实际使用的载体、设备与验证结果。
