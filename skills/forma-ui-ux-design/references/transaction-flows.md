# 分步办理、核对与退补

当用户要在多个决定之间来回修改，或另一人要根据已填资料作出决定时，先按用户要判断的问题分组。短而且需要同时比较的选项可以放在一屏。

## 让版式跟着判断顺序走

| 场景 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 填写借用申请 | 中央放当前字段，侧边列“场地与日期”“用途与设备”等可辨认的章节。附加条件紧挨触发它的选项 | 单列保留当前章节和标题。用可读的步骤名称表示进度，变长的条件分支可只显示所处阶段 |
| 配置商品 | 作品预览和规格选项并排。把尺寸、装裱差价、履约费用放在影响它们的选择旁，选项可同时看到名称和选中标记 | 调整选项后仍能找到变化的预览和总价。长标题、错误提示和系统键盘出现时，试滚到末项并操作底部按钮 |
| 核对或审批 | 让实际要判断的内容占主栏。核对页按填写时的章节排列，值与“修改该组”靠近。审批操作靠近申请编号、版本和待判断事实 | 各组依次展开，地点、时段、费用等关键值完整可读。单组修改完成后，回到核对页相应位置 |

用主动作色强调当前步骤的“继续核对”“提交申请”或“生成清单”。将保存草稿和返回编辑置于次一级。回执出现时再展示结果和下一步。审批员可以“通过”或“退回补正”时，给两个动作明确名称，按业务后果确定权重，避免默认选择影响判断。[W3C 分步表单](https://www.w3.org/WAI/tutorials/forms/multi-page/) · [GOV.UK 核对页](https://design-system.service.gov.uk/patterns/check-answers/)

若预览承担尺寸比较，在同一视口里切换最小和最大规格，检查物体相对共同参照物的大小。两种画幅在桌面有差异，缩到手机后却可能同时碰到容器上限，结果看起来一样。需要等比展示时保留同一参照面；展示纹理的放大图可另行标明比例。核对页仍要给出尺寸数字和单位。

## 改选后，以当前答案为准

用同一组适用条件生成字段、必填规则、核对内容和提交数据。选择“配送”时启用地址与运费，改成“店取”后核对门店、取件安排和新的合计。草稿可以按业务需要临时记住上一次输入，提交记录只收当前分支需要的数据。HTML 中仅隐藏一个已填写的输入框仍可能将它包含在 `FormData` 中。原生表单可禁用非适用字段组，自建状态则按当前选项构造提交数据。

从核对页修改答案时预填原值。若改选触发新问题，先补完这些字段，再直接返回核对。区分“适用但未填写”的可选项和“当前选择下不适用”的整组字段。加入可追踪的金额、附件或交接版本时，从同一份有效数据生成核对和最终记录。

## 用户怎样找到错误

提交时若错误分布在多个字段，在当前表单入口列出可操作的错误摘要，并把焦点移到摘要。每个链接先展开对应章节，再聚焦具体输入框。字段旁显示同一句修正提示，交代哪个值要改、如何改。用错误文案和字段边界表达出错，用独立焦点轮廓表示键盘位置。单一短输入可就近提示并聚焦。字段值和已选项在校验失败后保留。[GOV.UK 错误摘要](https://design-system.service.gov.uk/components/error-summary/)

## 退回后还能接着办

有退补环节时，审批面向一次已提交的内容。退回记录关联该次提交、原因和需要补正的章节。申请人再打开时，同时看见原值和原因，能直接进入对应字段。重提沿用同一申请编号，并使审批方可以辨认本次修订和上次决定。编辑草稿保留在申请人侧，直到提交成功再更新待审内容；若存在同时审批的可能，提交决定时核对当前版本和状态。

若评审需要回看依据，在提交事件上保留当时的有效字段快照或可查询的版本引用。查看“第 1 版”应读到第 1 版的资料。旧记录仅有决定和时间时，保留这些可核实的信息，并标明资料快照缺失。

验收时试一次跨分支修改和一次跨角色交接。例如填好配送地址后改为店取，检查核对页、合计和清单；再将同一份申请退回、补正、重提，核对单号、待审数量与历史原因。分别记录浏览器视口和实际手机键盘的验证结果。
