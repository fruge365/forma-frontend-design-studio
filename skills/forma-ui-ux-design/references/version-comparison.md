# 版本对照与差异审阅

让审阅人随时能说出正在比较哪份作品、哪个基准版和哪个候选版。把版本标识放在对应内容旁，例如“已发布 V2”和“待审 V3”。只有确有发布记录时才使用“已发布”。对照方向决定“新增”和“移除”的含义。若允许交换两版，同时更新前后值、变更说明和统计。

## 根据要找的差异选视图

GitHub 对图像提供并排、分界线擦拭及透明度叠加三种查看方式，并排时还会指出图像尺寸变化。代码审阅则可在双栏与单列差异之间切换。可将下列选择用于海报校样、内容编辑和系统配置。[GitHub 图像版本对照](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files#viewing-differences) · [GitHub 变更审阅](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request)

| 审阅人要判断的事 | 版式与行为 |
| --- | --- |
| 两稿的标题、层级和构图如何变化 | 并排看完整画面。用相同的显示比例、缩放和参照边缘。画布尺寸改变时写出各自尺寸，完整保留画幅。 |
| 同一位置的色彩或图形是否改变 | 对齐两稿坐标，用擦拭边界看同一处的两侧。只裁切显露区，内部画布尺寸恒定。辨认微小位移时可调叠加透明度。比例或裁切范围不同、缺少可靠对齐点时，先展示完整画面，并说明尺寸变化。 |
| 是哪个字段、条款或段落发生变化 | 以字段键或段落身份匹配，逐项标出新增、移除或修改。把变更前后的名称、数值、单位放在同一组。若顺序有含义，单独交代移位。 |

提供能脱离颜色读懂的事实，例如“场地由东厅改为西厅”“标题从左上移到中央”。用旧值与新值、位置说明或文字状态配合高亮；内容较长时保留变更处前后的一小段上下文。依业务含义分别显示零值、空字符串、未设置及已移除。两版完整且相同可显示“无差异”；筛选后没有命中、基准版本缺失、资源加载失败，各自给出相应的范围提示或恢复入口。

## 窄屏与操作

在用户需要读到的最小字号下试排。并排后看不清文字时，可在同一区域切换完整的两个版本，或将每个字段的前后值上下排列。保留正看的段落、字段或画布局部，切换后仍可就地核对。缩略图适合总览，需要辨认细线和小字时提供原尺寸或放大入口。

擦拭控件可用带名称的原生范围输入，标明比例描述哪一侧，例如“候选稿显示 60%”。允许点按轨道或用按钮调整到所需位置，键盘可用方向键微调、Home 和 End 查看端点。检验时分别用单次点按和键盘完成比较，并检查数值、分界线与可见画面同步。[W3C 拖动操作说明](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements) · [W3C 滑块交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

浏览操作只更新查看状态。若产品还支持批准、还原或应用，在该动作旁标明目标版本。需要保存意见时，将其关联到具体版本对和字段、段落或画布位置；再次定位时先核对原版本。

画面校样还要保留擦拭分界，以及意见落在画幅内的相对位置。进入标注模式后，点选海报应保留用户刚刚对齐的分界。排班或授权审阅则要交代何时生效：已有签发记录且规定下班次才启用的版本，需按本班所处的生效区间判断。

## 复核一次真实差异

选一对同时含文字修改和位置调整的海报，分别用桌面并排与手机单稿找回同一处改动。把擦拭边界移到两个端点和中间，检查未改动的元素始终重合。再用一对包含数值 0、新增字段和被移除字段的配置，核对清单的前后值，确认只浏览时当前生效版本始终一致。
