# 屏幕、纸面与可重印单据

先问拿到这张纸的人要做什么。读文章时通常沿用正文顺序，用打印样式调整行宽和分页即可。现场观众要在几秒内找到下一场的时间和地点，交班人员要认出旧单对应哪一班、哪些事项还没办完。这类任务值得单独编排纸面内容。

香港管弦乐团《铜行百载》室乐场刊的目录按曲目和表演者提供页码，乐季订购表则把日期、场次和选区放进可填写的表格。由此可推导，纸面层级应由读者的动作决定。节目单让时间、节目、场地排在同一阅读路径；交接单让单号、班次和待办归属在纸张离开屏幕后仍可核对。[港乐室乐场刊](https://www.hkphil.org/f/page/22513/33065/HKPhil_CMS_HseProg_05_170x247mm_24%204pp_20210827%20%281%29.pdf) · [港乐乐季订购表](https://www.hkphil.org/f/page/27105/50457/2627_Booking%20Form.pdf)

## 让范围进入纸面标题

“周六全部 5 场”和“我的节目 3 场，含周日”是两份不同的文件。把所选日期、范围或数量写在打印入口和纸面抬头。用户选了跨日项目时，按实际日期分组，即使屏幕当前只看其中一天。选择为空时提供返回挑选的入口。页面按钮与浏览器自带的打印命令都应有可解释的范围。让预览、快捷键打印和页面按钮读取同一份数据及顺序，换日期或退出某份旧单后再试一次。

业务单据按用户身份和打印用途选择字段。在正式交接时固定单号、时间、事项及责任人，保留快照或能读回原值的版本。草稿预览应在纸面写明“草稿”；从历史记录打印则取该单生成时的数据，后续改派人员、切换班次或更新库存均不应改写旧单。若某份草稿的数据无法保存，界面告知保存结果并保留可继续编辑的内容。[分步办理与版本记录](transaction-flows.md)

浏览器也可能在打印预览关闭时触发 `afterprint`。可在事件中恢复界面和焦点。把确认交接、库存变更或签收留给各自的业务动作。关闭系统对话框后，用户仍可核对草稿、修改选择或再次打印原单。[MDN 打印事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/afterprint_event)

同一物件有多次记录时，纸面标题或副标题要让持有人认得本次记录。例如陶器初烧与复烧共用作品名，可分别显示各自的档案号、出窑日期和窑温。验收时选同名对象中有差异的一对，直接从两份输出文件读回那项差异。

## 用纸张宽度排内容

保留能帮助识别品牌或单据的字形、标题和分隔线。把交互控件换成已选值，长名称和备注完整换行。用黑白文字显示“未处理”“已交接”等状态。使用 `@media print` 移除固定栏、裁切、滚动区和桌面最小宽度；用 `@page` 设置目标纸型及页边距，让正文落入可用宽度。优先采用可选择的文本。[MDN 打印样式](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing)

让日期标题与其第一场连在一起，短事项尽量整项落在一页。让超过一页的长备注按段落继续排，避免在整张表上设置 `break-inside: avoid`。多页表保留语义化 `thead`，核对续页是否实际出现列名。单据可能拆页传递时，为每页保留单号或其他足以辨认归属的标识，给页眉页脚留出空间。核对目标浏览器默认加上的网址、日期和页码是否遮挡内容。[MDN 分页控制](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Fragmentation) · [W3C 表头与页间重复](https://www.w3.org/TR/CSS22/tables.html)

## 检查交给读者的文件

按交付纸型实际生成 PDF，记录缩放、背景图形和浏览器页眉页脚设置。用跨日选择、空集合、超长事项或历史版本中与当前不同的一项作为样本。按页检查首条、跨页处、末条、总数与单号，确认预览里的筛选结果、字段值和顺序都进了文件。把 PDF 页转成图或在阅读器中逐页看，检查截列、空白尾页、灰度状态和底边遮住的末行。需要搜索或复制的单据，再从文件中检索一个单号与一段中文。只有确实检查过目标打印机，才记录实物边距与细线的表现。

写验证结果时说明实际经过的环节。拦截打印按钮可核对调用对象，派发打印事件可检验页面状态，浏览器导出的 PDF 才能检查实际分页。系统打印窗口中的取消行为需要在相应窗口操作验证。
