# 第七轮 · 明暗外观、阅读位置与舞台提示

第六版已经要求为深色主题重新选色。本轮补充三个实际决定：页面打开期间系统改变配色时，怎样保留用户的明确选择；长文放大后，从哪个段落接续；操作员选择了另一条提示后，台面上哪些状态应该改变。[外观偏好、阅读位置与动态反馈](../frontend-design-studio/references/appearance-and-reading.md)

## 深浅主题的合成色

同一套 CSS 透明度在不同表面会得到不同的颜色。试验用 Chromium 渲染实色色块，从截图中央采样，按合成后的 RGB 相对亮度计算对比度。下表记录的是独立色块试验。

| 背景 | 前景 | 合成后的 RGB | 对比度 |
| --- | --- | --- | ---: |
| #F5F1E6 | #1C2329，44% 不透明度 | 149, 150, 147 | 2.635∶1 |
| #F5F1E6 | #1C2329，70% 不透明度 | 93, 97, 98 | 5.552∶1 |
| #17252D | 白色，38% 不透明度 | 111, 120, 125 | 3.479∶1 |
| #17252D | 白色，62% 不透明度 | 167, 172, 175 | 6.844∶1 |

两组较高不透明度的文字超过 4.5∶1。更换背景、叠加选中状态或浮层后应按实际颜色重算。字号、字重和观看距离仍需在目标设备上判断。[W3C 文本对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 怎样评审两个样页

| 样页 | 可复查的路径 |
| --- | --- |
| 折页 · 活字印刷札记 | 读到章节中间，把文字放大、行距调宽，再关闭设置和刷新页面。检查阅读线附近是否还是刚才那一段。切换“跟随系统”与手选暗色，观察页面和控件。 |
| 候场 · 舞台提示台 | 在 Q01 执行时打开 Q04 预览，依次查看当前、待执行和所选提示。把 Q04 设为待执行，再执行、查看记录并撤销。 |

对于会切换主题的页面，需分别保留用户所选模式和实际显示的亮暗。实测在跟随系统时页面响应系统变化，手选与系统恰好相同的颜色后，系统下次再变，手选值仍有效；恢复跟随时，页面立即采用此刻的值。[MDN 系统配色偏好](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme)

## 从试用观察到的修改

**阅读器。** 四章共 16 段正文。初版关闭设置时浏览器会为了聚焦工具栏而滚动，在第三章操作后可能落到第二章。调整工具栏及正文留位后，分别在第二章第 3 段和第三章第 2 段切换字号、行距与暗色，再关闭设置、刷新或重新进入，阅读线仍能回到原段。Esc 也能把键盘焦点还给设置按钮。桌面首屏导语原先有孤立的“印。”，缩短文案后在 1440px 与 390px 均完整呈现。反字与纸面示意保留纸张和印迹本色，环绕文字与界面随主题变化。

**提示台。** 初始为 Q01 已执行、Q02 待发。预览 Q04 保留这两个状态，设为待发后变为 Q01 和 Q04，执行后变为 Q04 和 Q05，并记录跨过的两条提示。刷新后撤销可恢复先前状态，日志保留撤销记录。预览名称、当前及待发区域和执行按钮的标注锚点带有提示编号，标记不会落到另一条提示的同名控件。

阅读器在 320–1440px 七种宽度下检查，提示台在 320–1920px 八种宽度下检查。提示台在 1280×720 和 1920×1080 下可以整屏展示。系统颜色与减少动态使用浏览器媒体偏好模拟，实际低照度、远距辨识和移动系统大字体仍需在目标环境检验。

**外观标注。** 在评审画布内切到暗色、大字号、宽行距后标注一段正文，意见卡和导出文件保留当时的设置。若之后改为亮色，定位提示同时给出当前外观与原外观。导入第六版设备编号、旧评分及意见后仍能读取原值。

## 换成博物馆讲解手册

独立试用者只读取新版 skill 和社区博物馆需求，制作了带讲解员稿件与访客视图的手机手册。在 390×844 视口中，讲解员预览第二站的杆秤时，另一个访客标签仍显示第一站木牌；按“宣布抵达”后，访客才看到第二站。暗色且减少动效时，同样能核对第三站的切换。

在讲稿中途将正文从 19px 放大到 28px，并调宽行距，试作按句子恢复。测得同一句锚点相对阅读线的偏移约为 0.34px，刷新后仍可接续。试作检查了 320、390、768、1440px 四种宽度，仅模拟同一浏览器内的标签页同步。
