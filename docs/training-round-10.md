# 第十轮 · 版本对照与差异审阅

展览海报要看构图和字形是否变化，权限审阅要追踪某一项授权在新旧版本中的实际范围。本轮让两套页面分别处理这两类判断。[版本对照指南](../frontend-design-studio/references/version-comparison.md)

## 参考与设计选择

GitHub 的图像审阅支持并排与擦拭。Apple 中国大陆的 iPad 机型比较页将各机型的屏幕尺寸、显示屏类型等放在相同指标下。两者启发了不同的设计：校样室对齐画幅与参照边缘，权限表按稳定的能力标识组织前后值。标识顺序变化后，同一权限的范围仍可追溯。[GitHub 图像对照](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files#viewing-differences) · [Apple 机型比较](https://www.apple.com.cn/ipad/compare/)

## 浏览器复核

校样室在 320–1920px 的十二种宽度下检查。实图中原有构图线条穿过展期，改成独立底栏后日期和场地可以在两稿上直接对读。权限页在同一范围的十四种宽度下检查。手机保留每一项的两版标签与文字状态。只浏览、筛选或取消确认时无审阅记录；明确确认后可在刷新和同源另一标签页读回。

标注与擦拭共用画布。如果点选海报时先移动分界，意见就会记录成另一种画面。评审台现在向样页同步标注模式，同时保存所比较的两份稿件、擦拭分界和点击在画幅内的相对位置。浏览器复核把初稿露出宽度设为 23%，在画面左侧标注，切为并排后定位意见，检查分界与图钉。另导入一条旧版本对意见，核对它不会覆盖现有分界。权限页也为意见保留 V2.4 和 V2.5 的版本方向。[可运行的浏览器回归](../scripts/comparison-browser.cjs)

## 换成园林养护交接

独立试用者只读取新版技能及相关参考，用三种视口测试两份浇灌计划。西门月季圃在草案中换了次序，浇灌时长从 10 分钟改为 0 分钟，另一块花圃的时长尚未填写。查看较晚的 V3 草案时，交接页仍能指出晚班执行已签发的 V2。技能补充了跨班次时的判断依据：有延迟生效规则的项目，需要按对应班次的生效区间确定执行版本。试用验证了浏览器内的行为，户外手机阅读仍需现场检验。
