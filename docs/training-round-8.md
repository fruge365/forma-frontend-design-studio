# 第八轮 · 图上位置与业务对象

河岸导览需要回答“桥在河的哪一段”，仓内盘点需要回答“要登记的是哪一个货位”。前者用河道、桥梁、街廓和建筑立面建立印象；后者用月台、巷道、排号、列号帮助复核地址。两个样页从同一份对象数据生成图与目录，采用不同的版式、字体和状态表达。[空间界面设计指南](../frontend-design-studio/references/spatial-interfaces.md)

## 从哪里得到设计依据

故宫博物院的[主题导览手册](https://young.dpm.org.cn/uploads/1/file/public/202505/20250516181259_97digy9q27.pdf)让多条路线共用地点编号。Apple 的[地图“附近”说明](https://support.apple.com/zh-cn/guide/iphone/iphbaf51b2c0/ios)则说明移动地图可以改变搜索区域。这两种用法提示了不同的设计选择：地点编号需要稳定，列表的范围是否随视野变化则取决于用户的任务。本轮两张图的范围固定，不接外部地图服务。

## 浏览器试用改变了哪些细节

- 库区平面上的货架即使不符合筛选，也应留在原处帮助辨认巷道。实测时发现，灰显货架仍有可测坐标，标注程序只按坐标判断就会误以为它仍是可选结果。现在灰显货位不显示标注图钉；主动定位才恢复它。如果“手持扫码器”仍匹配 B-03，只清除与它冲突的库存状态，保留关键词。
- 给地点 03 的详情标题留意见，换到 05，图钉随原对象隐藏。导出 JSON 后在全新的浏览器上下文导入，再点定位，可以重新看到四跨梁桥的标题。Markdown 评审单同时写出“详情标题 · 地点 03”。
- 给 A-01 的实盘字段留意见，再打开 B-03 的盘点表单。定位旧意见只提示应打开 A-01，B-03 不会被替换。另测在 A-01 数量框输入 17 后，从评审台定位 B-03 的标题，原表单和未保存的数字都保留。第七版阅读器的主题、字号及评分也可以随旧反馈导入。[可重跑的浏览器回归](../scripts/spatial-browser.cjs)

## 图面测量与迁移

在 320、390、768、1024、1440 CSS px 五种宽度下，逐个命中测试了六个建筑和十六个货位。110 次中心点检查均落在对应控件上，未发现相邻目标矩形重叠、重复锚点或整页横向溢出。在 320px 宽度下，建筑热区为 44 × 44px，货位最小约 62 × 44px。这些是样页的实测值，不代表所有地理点都应采用同一尺寸。另行检查了两页直至 1920px 的布局。

独立试用者只拿到新版 skill 和双厅电影节选座需求，制作了手机选座原型。两厅共用南门，分别在大厅左转、右转；选座同时显示相对银幕的排数及左右侧。切到另一场时，旧场可选的 A 排 03 号在新场已占用，不能保存。复核还覆盖“相同座号在两场都可选”：分别保存 A 排 02 号，将第一场改成 D 排 04 号后，第二场刷新仍是 A 排 02 号。因此在[预约选座指南](../frontend-design-studio/references/workspace.md)和空间指南间加了交叉链接，并说明业务记录应以场次区分同名位置。

本轮验证覆盖浏览器宽度、键盘、点击命中和本地记录。建筑与仓库均为虚构，示意图不按比例；馆内导航、真实库存以及手机真机辅助技术需在相应项目中另行验证。
