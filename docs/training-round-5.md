# 第五轮 · 核对、改选与退回补正

第四版已覆盖移动草稿、表单分组和审批队列。从核对页改选条件时，还需要回答三个问题：旧字段是否参与校验，改完应回到哪一组，审批员看到的是哪一次提交。本轮把这些判断写入同一份场景参考，同时用企业办理和消费配置两种页面检验。[分步办理、核对与退补](../frontend-design-studio/references/transaction-flows.md)

## 两种布局

| 样页 | 页面把空间留给谁 | 可以复查什么 |
| --- | --- | --- |
| 栖原 · 场地借用 | 申请人需要看清当前章节、附加条件和保存状态。值班员需要在作出决定时看到已提交的资料、单号和历史版本。 | 在核对页改设备选项，退回某一组资料，再以同一单号补正。 |
| 汀印 · 版画装裱室 | 宽屏让作品与规格并排，纸张和画框随选择变化。手机沿作品、规格、交付方式和合计的顺序阅读。 | 选择有加价的画框与配送，再从核对页改为店取，比较预览、费用和保存的清单。 |

试排时，两款画幅在手机上碰到了同一个容器上限，看上去一样大。调整后，在 320、390、620、768、1024、1440px 六个宽度下分别切换，两款均能在同一墙面呈现相对差异。这条检查已写回指南。费用也可直接复算，大张画纸 ¥278、胡桃木框 ¥150、配送 ¥18，合计 ¥446。改为店取后为 ¥428，本机清单排除旧地址。

## 条件字段的复现

在原生 HTML 表单中各测了一次“配送改店取”和“扩音改原声”。分别填写地址、设备后只隐藏字段，Chromium 的 `FormData` 仍包含旧值；清空已隐藏的必填字段，`checkValidity()` 仍会失败。停用非适用字段组后，两个表单都可提交，有效数据分别是 `{"mode":"pickup"}` 和 `{"mode":"acoustic"}`。重新启用字段可以恢复临时输入。

因此要让显示、必填校验、核对信息、总额和最终记录都使用当前有效选项。前端自行组装数据时要显式选择字段。草稿是否保留上次输入，由具体业务决定。[HTML 表单数据构造](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#constructing-the-entry-list)

用户从核对页修改一组时，先预填已有答案。如果新选择引出了其他问题，请先处理新字段，再回到核对。多个错误需要摘要时，链接应能把焦点带到具体输入，字段旁保留同样的修正提示。[GOV.UK 核对页](https://design-system.service.gov.uk/patterns/check-answers/) · [GOV.UK 错误摘要](https://design-system.service.gov.uk/components/error-summary/)

## 评审台的复查方式

两个新样页的意见会附上固定的步骤名称。标记只在对应步骤显示，定位时如处于其他步骤，会提示评审人先打开哪一步。浏览器实测覆盖了跨步骤切换、原生清单对话框中标记的鼠标命中、刷新、JSON 与 Markdown 导出，以及第四版布局标注和评分的导入。第五版评审文件仍使用原来的 `forma-review/v1` 格式。

## 一份申请的两次提交

用同一单号从填写、保存草稿、核对、送审走到退回补正，再修改活动标题和扩音安排，重提并批准。第二版批准后展开第一版，仍能读到原活动名和“不需要扩音”；第二版展示新活动名和话筒说明。退回原因留在对应版本。旧记录如果没有保存快照，界面会说明缺失。两个浏览器标签同时提交测试只生成一次提交事件。另验证错误提示能定位相应控件、人数超出场地容量会阻止继续，以及 320 至 1440px 八个宽度的布局。

## 独立试用

另一位执行者只读取更新后的 skill 和杂志社授权申请需求，制作了纸刊与播客两种授权方式的试作。在 390×844 视口先选纸刊 2400 册，返回改为播客 12 分钟，核对页和提交记录只保留播客时长。作者修订草稿时，编辑仍看到上一版。第二版送审后，编辑可以在 1440×900 的正文与反馈双栏中展开第一版及其退回原因。该次试用另外检查了 320px 和 768px 宽度。

这一轮验证的是独立 HTML 在 Chromium 中的办理、标注和本机状态。申请审批与版画清单使用演示数据。原生 App 系统键盘、微信真机、服务端并发及跨设备同步需要在相应运行环境验证。
