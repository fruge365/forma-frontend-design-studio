# 前端设计工作室

从真实内容和用户动作确定页面的视觉主次，把版式、交互状态、响应式布局一起落实到前端代码。

## 开始前

先看项目已有品牌、组件、数据与设备要求。用一句具体的话明确“谁、在什么设备上、依据什么信息、完成什么动作”。从这句话确定首屏最大的对象，以及最先出现的操作。例如园区值班员在值守屏上先看异常区域和影响设备，再转到异常清单处理。窄范围修改沿用既有体系。

## 选择参考

新建页面或重做视觉方向时，先选主视觉、素材与文字构图，参阅 [视觉方向与首屏构图](references/art-direction.md)。需要确定栅格、中文字阶、色彩、动效或组件状态时，参阅 [视觉基础](references/design-foundations.md)。按当前页面的主要任务读取场景指导。

## 实现

1. **以内容试排首屏。** 放入实际长度的标题、决定行动所需的信息和一个明确的主行动，再决定图片位置、内容宽度及下一区块。素材、图表或记录列表中的哪一个占据最大面积，应当能用当前任务解释。
2. **为视觉角色命名。** 先区分文字、表面、动作、选择、告警、焦点等角色，再从品牌体系映射色值。用间距表达分组，用字阶表达信息重要性。已有设计系统优先。新项目可从 [语义 token 示例](assets/tokens.css) 选择需要的部分。
3. **实现主路径及其状态。** 搜索、筛选、弹层、提交和返回应改变对应内容或状态。使用场景需要的加载、空、错误、成功反馈。原型采用标明来源的演示数据，操作结果明确写出是否仅保存在本机。
4. **用真实视口校准。** 在目标桌面或大屏和代表性窄屏检查裁切、字阶、触控、键盘焦点及动态反馈。给出运行入口、已验证的操作和剩余限制。用户要求本地评审时，验证实际监听地址和 HTTP 响应后再报端口。
