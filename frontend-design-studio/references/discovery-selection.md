# 搜索、筛选、对比与批量处理

## 让用户辨认或核对对象

选材料时，先让纹理、名称与影响初选的属性相邻。用一致的取样尺度、光照或标注，让人知道缩略图能比较什么。花纹、色卡与状态同时给文字名称。进入对比后，以对象为列、属性为行，把厚度、幅宽等数值换为同单位，并区分“未知”和零。窄屏可按属性逐组列出候选值，或在对照表内横滚，始终能辨认正在对照的对象。

逐台核验设备时，优先让编号、位置、状态与可办事项按列对齐。详情放次级信息，筛选和批量操作靠近所作用的记录。先区分选择颜色与业务状态色，同时提供选中标记、状态文字及不可操作原因。

在手机上，一行或一张卡常常同时提供“打开详情”和“勾选”。给两个动作各自留出触控区域。可在保留小方框外观的同时扩大标签的可点击留白。试点方框边缘和相邻名称，前者应只改变勾选，后者应只进入详情。网页按真实 CSS 视口检查，原生项目按目标端的单位和实际热区检查。

## 说清筛选了什么

- **定义集合，再排控件。** 若用户可接受木材或石材，同组多选取并集；材质、色调和关键词共同限制结果。若用户要求场地“同时有投影和无障碍入口”，两项设施需要取交集。检索范围应说明可搜名称、编号还是正文。
- **让计数有对象。** “3 个结果”指符合已应用条件的完整集合，排序后再分页。若显示分组选项数，明确是该选项单独能命中多少，还是追加后总共能看到多少。例如暖色木材有 2 件，暖色石材有 1 件，追加石材后共 3 件。“石材 1”与“应用后显示 3 件”分别回答两个问题。没有可靠总数时，可展示已加载数并注明范围。
- **安排生效时机。** 少量快速选择可立即更新。需要组合多个条件、查询延迟较长或手机面板挡住列表时，可先编辑草稿。打开时从已应用条件复制；取消、关闭或按约定返回时丢弃草稿；点击应用后同步列表、数量、条件标签与页码。面板关闭后仍能看见已应用的筛选，并可单独移除。异步检索仅让与当前查询一致的响应更新画面。[Carbon 筛选指南](https://carbondesignsystem.com/patterns/filtering/)
- **让零结果有退路。** 展示导致零结果的关键词和条件，优先提供能保留其他条件的恢复操作。能重新计算时，可写“移除冷色后查看 1 件”。数据尚未载入、加载失败、库内本来没有记录应提供各自的下一步。筛选后超出末页时回到有效页。

移动筛选按钮可显示已应用数。关闭面板后把键盘焦点还给入口；结果计数可以单独播报。桌面逐项勾选时保留当前复选框的焦点，让键盘用户接着选择。卡片上的详情链接与“加入对比”分设控件，读屏名称中带上对象名称。

## 从详情回到当时的列表

需要分享的公开列表条件、排序、有效页码和对象编号可放入 URL，未应用的草稿与批量勾选范围按业务留在当前工作会话。进入详情前记住触发项 ID 和滚动位置，浏览器返回与页内返回都需恢复已应用结果，并把焦点还给原条目。若记录已经消失，则定位到仍可理解的相邻结果或结果标题。直接打开详情时提供回到目录的入口。Web 单页实现可用历史记录区分详情跳转与当前列表状态更新，实际测试返回、前进和刷新。[MDN History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API)

## 比较候选与执行批量操作

比较篮可以跨搜索条件保留候选，显示名称和移除入口。即使某项暂不在当前结果中，用户也可以把它带入同一张对照表。设数量上限时，在尝试超限处说明原因，并允许回到已选项调整。

批量操作会改变记录。将作用对象写进按钮或工具栏，如“勾选本页可办理的 8 台”；只有业务支持时，再单独提供“扩展到本次筛选的全部 36 台”。按稳定 ID 记录选择。筛选变化后可清除失效选择并说明，也可让用户核对保留的跨页清单。执行前区分选中数、可办理数和跳过原因，状态可能变化时，在提交处重新核对资格。撤销只恢复此次实际改变的记录，遇到后续改动按业务规则处理。[Carbon 数据表](https://carbondesignsystem.com/components/data-table/usage/)

验收可使用一个包含跨页条目和不可办理条目的结果集。用键盘取消未应用的筛选，移除一个导致零结果的条件，再从详情返回。最后验证比较篮的候选、批量预览的对象与实际变更能各自对上。
